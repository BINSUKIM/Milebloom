# Milebloom

**당신은 달리고, 차는 풍경을 그립니다.** — *Every mile, painted by your car.*

Milebloom은 차가 아는 것들 — 와이퍼가 움직인 시간, 헤드램프를 켠 밤, 창문을 열어둔 바람 — 으로 하나의 풍경을 그리고, 운전이 쌓일수록 그 풍경이 자라나는 차량 내장 앱입니다.

Pleos Connect(AAOS)용 인포테인먼트 앱이며, 모바일 앱이 아닙니다. 차와 풍경은 카메라 영상이 아니라 앱이 그리는 그림입니다.

> **이 저장소는 1차 제출용 프로토타입입니다.** 위 소개는 완성된 제품의 설명이고, 지금 동작하는 범위는 아래 [구현 범위](#구현-범위)에 따로 적었습니다. 동작 확인은 모두 **Pleos Connect Emulator v2.1.0**에서 했습니다. 실차에서는 시험하지 못했습니다.

- 패키지 `com.milebloom.app`, 최소 API 34

## 실행 방법

에뮬레이터 준비는 [테스트 환경 및 필요한 설정](#테스트-환경-및-필요한-설정)을 먼저 보세요.

### APK로 실행 (권장)

```bash
adb install -r apk/김수빈_Milebloom_release.apk
```

기기 앱 목록에서 **Milebloom**을 실행합니다. 앱은 시동만으로 켜지지 않으며 사용자가 직접 실행합니다. 첫 실행 때 기어 P에서 권한 안내 카드가 뜹니다. [계속]을 누르면 권한 창이 두 번 뜨니 모두 허용하세요. 위치(주차 지점 조회)와 차량 속도(정차 판별) 권한입니다. 에뮬레이터에서는 속도 권한이 '위치 정보', Pleos 위치 권한이 '알 수 없는 작업'으로 표시됩니다. 거부해도 앱은 동작하고, 앱 안 **설정 › 위치·속도 권한**에서 다시 물을 수 있습니다.

이미 다른 서명의 빌드가 설치돼 있으면 설치가 거부됩니다. 먼저 지우세요.

```bash
adb uninstall com.milebloom.app
```

### 소스에서 빌드

```bash
./gradlew testDebugUnitTest
```

```bash
./gradlew assembleDebug
```

```bash
./gradlew assembleRelease
```

| 결과물 | 경로 | 비고 |
|---|---|---|
| debug | `app/build/outputs/apk/debug/app-debug.apk` | 바로 설치 가능. 신호 패널·시험 버튼·검증 화면 포함 |
| release | `app/build/outputs/apk/release/app-release-unsigned.apk` | **서명 키가 저장소에 없어 서명 없이 만들어지며, 그대로는 설치되지 않습니다.** 설치용 release는 `apk/`의 파일을 쓰세요 |

서명 설정은 `~/.milebloom/signing.properties`가 있을 때만 적용되며, 없어도 빌드는 성공합니다.

## 테스트 환경 및 필요한 설정

### 1. 빌드 도구

| 항목 | 값 |
|---|---|
| Android Studio | 2026.2 (AGP 9.4.1을 지원하는 버전) |
| JDK | 25 — Android Studio 내장 JBR이면 됩니다 |
| Android SDK | Platform 37 (`android.car` 선택 라이브러리 포함) |
| Gradle | Wrapper 9.6.0 (자동 다운로드) |

터미널에서 빌드하면 위치를 직접 알려 줘야 합니다. macOS 예시입니다. Android Studio로 프로젝트를 열면 SDK 위치(`local.properties`)는 자동으로 만들어집니다.

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
```

```bash
export ANDROID_HOME="$HOME/Library/Android/sdk"
```

### 2. Pleos SDK

**따로 받을 파일도, 넣을 인증 정보도 없습니다.** Vehicle·FusedLocation·SpeechToText·TextToSpeech SDK는 `settings.gradle.kts`에 적힌 Pleos Maven 저장소(`https://nexus-playground.pleos.ai/repository/maven-releases/`)에서 빌드 때 자동으로 받습니다. 인터넷 연결만 필요합니다. NaviHelper SDK는 쓰지 않습니다.

### 3. 에뮬레이터

[Pleos 시작하기 문서](https://document.pleos.ai/en/docs/pleos-only/getting-started)를 따릅니다.

1. Android Studio **SDK Manager > SDK Update Sites**에 Pleos가 안내한 Pleos Connect Emulator 다운로드 URL을 추가합니다.
2. **SDK Platforms**에서 API 34 Pleos Connect 시스템 이미지를 설치합니다.
3. **Device Manager > Create device > Automotive**에서 Pleos Connect 기기를 만듭니다. 문서 기준 Cold boot, RAM 4 GB입니다.

확인에 쓴 환경은 Apple Silicon Mac, `Pleos_Connect_v2.1.0` AVD(API 34, arm64-v8a)입니다.

앱은 에뮬레이터의 **user 10**으로 돕니다. `pm` 명령과 브로드캐스트에는 `--user 10`을 붙여야 합니다.

## Virtual Console 시연 절차

에뮬레이터 안 웹 서버인 Virtual Console로 차량 신호를 넣습니다.

```bash
adb forward tcp:18088 tcp:8088
```

```bash
open http://127.0.0.1:18088
```

**브라우저의 Console 탭을 앞에 띄워 두세요.** 닫혀 있거나 탭이 뒤로 가면 주입이 503 오류로 거부되거나 조용히 무시됩니다. 주입 전에 상태를 확인할 수 있습니다.

```bash
curl -s http://127.0.0.1:18088/vehicle/state
```

release APK 기준 순서입니다. 앱을 켜고 기어 P에서 시작합니다.

| # | Console 요청 | 화면에서 볼 것 |
|---|---|---|
| 1 | 앱 실행 (기어 P) | 멈춰 있는 그림 풍경과 그 앞의 차, "오늘도 잘 다녀오세요."와 [음성 기록]·[설정] 버튼 |
| 2 | `POST /vehicle/gear?gear=Drive` | 글자와 버튼이 즉시 사라지고 주행 톤으로 바뀝니다. 오른쪽 아래에 음성 기록 버튼만 남습니다. **속도가 0이면 정차로 판정해 아직 흐르지 않습니다** |
| 3 | `POST /vehicle/controls?speed_kph=40` | 풍경이 5초에 걸쳐 흐르기 시작하고 바퀴가 돕니다 |
| 4 | `POST /vehicle/lights?feature=headlamp_mode&value=LowBeam` | 차 헤드램프가 켜지고, 낮이었다면 약 20초에 걸쳐 밤 톤으로 바뀝니다 |
| 5 | `POST /vehicle/body?window_fl=100` | 그림 속 차의 앞 창문이 열립니다 |
| 6 | `POST /vehicle/body?front_wiper=Low` 후 30초 넘게 기다린 다음 `front_wiper=Off` | 화면 변화는 없습니다. 비로 집계되어 8번의 색이 달라집니다 |
| 6-1 | `POST /vehicle/odometer?traveled_distance_km=<지금 값 + 30>` | 화면 변화는 없습니다. **주행 중에는 새 요소를 그리지 않습니다.** 이 거리가 8번에서 숲을 키웁니다 |
| 7 | `POST /vehicle/controls?speed_kph=0` | 약 2초 뒤 정차로 판정하고 6초에 걸쳐 흐름이 멈춥니다 |
| 7-1 | (화면) 오른쪽 아래 마이크 버튼을 한 번 누름 | 시작음 → 받아쓰기 → "기록했어요."(음성). 에뮬레이터의 음성 인식은 말과 관계없이 "안녕하세요"를 돌려줍니다 |
| 8 | `POST /vehicle/gear?gear=Park` | 하늘이 오늘의 색으로 물듭니다. **Console의 AMBIENT 패널에서** 색이 바뀝니다. 1.5초 뒤 도착 인사 한 줄과 음성, 약 4초부터 **이번 주행으로 생긴 나무·덤불·개울·풀이 하나씩 밑단에서 자라납니다.** 다 자란 뒤 [음성 기록 · 확인 전 n]·[설정] |
| 9 | (화면) [음성 기록 · 확인 전 n] | 이번 주행에서 남긴 말을 확인·수정·삭제합니다. 뒤로 가면 시간순 전체 목록 |

예시:

```bash
curl -X POST "http://127.0.0.1:18088/vehicle/gear?gear=Drive"
```

- 에뮬레이터 화면에는 실내 조명이 없습니다. 조명 색은 Console 스와치와 `vehicle/state`의 `ambient_light`로 확인합니다.
- 앱은 조명의 색만 바꾸고 스위치와 밝기는 건드리지 않습니다. 색은 기어 P 체결 때 한 번만 씁니다. 주행 중에는 바꾸지 않습니다.
- **에뮬레이터의 주행거리는 저절로 늘지 않습니다.** 속도를 넣어도 누적 거리에 더해지지 않습니다. 그래서 6-1번처럼 Console로 누적 주행거리를 직접 넣어야 숲이 자랍니다. 앱은 이 값을 실차와 같은 SDK 경로(`getCurrentDistanceDriven`·리스너)로 받아 D 진입 때와 P 체결 때의 차이를 구간 거리로 씁니다. 거리를 넣지 않은 주행은 0 km라 숲이 자라지 않습니다. 곧은 길 비율도 거리가 있어야 계산되며, 그 계산은 단위 테스트로 확인했습니다.
- 숲은 한 번의 주행에서 거리 20 km에 1만큼, 많아야 1.5만큼 자랍니다(30 km 이상은 같습니다). 처음 설치한 숲은 싹이 몇 개 돋은 빈 들판이고, 30 km 이상 주행을 두 번 하면 덤불이 생깁니다. 나무는 누적 8(약 6번)부터입니다. 단계 숫자나 보상 문구는 화면에 나오지 않습니다.
- 비(와이퍼 수동 작동이 주행 시간의 30% 이상)는 웅덩이, 60% 이상은 개울, 주행 중 운전석 밖 도어 열림은 새, 창문 열림은 홀씨, 헤드램프를 켠 밤은 반딧불·달이 됩니다. 들판 요소는 그달에만 보이고 다음 달에는 새 들판이 시작됩니다.
- Console의 속도 모의는 실행마다 다르게 움직였습니다. 40을 넣으면 그대로 유지될 때도, 약 20초에 걸쳐 0으로 줄어들 때도 있고, `speed_kph=0`이 바로 먹지 않을 때도 있습니다. 3·7번 전후로 `vehicle/state`의 `controls.speed_kph`를 확인하세요. 줄어들면 3번을 다시 보내고, 안 멈추면 감속을 기다립니다. P로 바꿔도 속도 값이 남을 수 있으니 다시 시연할 때는 먼저 0인지 확인합니다.
- 낮·밤은 **서울 기준 실제 해 진 시간**으로 정합니다. 해가 진 뒤 시험하면 처음부터 밤 톤이고, 에뮬레이터 상태 표시줄의 시계와는 다를 수 있습니다.

**신호 수신 확인** — 앱을 켠 직후 로그에서 신호별 지원 여부를 볼 수 있습니다. 기대하는 결과는 `지원 …: Supported`이고 `예외` 로그가 없는 것입니다. `SPEED`만 권한을 허용하기 전에는 `Unsupported`로 나오고, 허용하면 `Supported`로 바뀝니다.

```bash
adb logcat -s MBSIG:I MBVEH:E
```

**내비 옆 분할 화면** — 앱 오른쪽 끝 손잡이(⋮)를 왼쪽으로 끌면 열립니다. 다시 끌면 앱이 사라지므로 앱 목록에서 다시 실행합니다.

**debug 빌드 전용 조작** — 해·달·차종을 바꾸고, 시연 시작 상태를 만들 수 있습니다. release에는 없습니다.

```bash
adb shell am broadcast --user 10 -a com.milebloom.app.SCENE --es sun down --ei month 4 --es car TUCSON --ez hud false
adb shell am broadcast --user 10 -a com.milebloom.app.SCENE --ef km 348.8   # 주행 없이 누적 거리를 더함(시연 시작 상태). 기록에 debug 거리로 따로 남음
adb shell am broadcast --user 10 -a com.milebloom.app.SCENE --ez forestReset true   # 풍경만 처음 설치한 상태로
adb shell am broadcast --user 10 -a com.milebloom.app.SCENE --ei uxActive 511   # 제한 강화 흉내 → Lv3, -1이면 해제
adb shell "am broadcast --user 10 -a com.milebloom.app.SCENE --es memo '세차 맡기기.'"   # 음성 인식 없이 음성 기록 한 줄 넣기
```

## 구현 범위

**1차 제출본의 범위는 주행 화면, 주차 화면의 도착 인사·숲 성장 연출·음성 기록·설정, 숲 성장 저장, SDK 연동 계층입니다.** 전국 지도는 2차 심사를 목표로 합니다.

### 동작함 (에뮬레이터에서 확인)

| 기능 | 내용 |
|---|---|
| 기어로 나뉘는 화면 | AAOS `GEAR_SELECTION`으로 승차(P)·주행(D)·도착(P) 구분. R·N은 경계로 치지 않습니다 |
| 주행 풍경 | 벡터 에셋으로 그린 레이어 풍경이 30 fps로 흐름. 단독·분할 화면. 먼 산은 모양이 다른 조각 6장을 고정된 순서로 이어(앞·뒤 두 겹의 순서·길이·속도가 다름) 같은 산이 일정 간격으로 되풀이되지 않고, 풀은 4종·낮은 꽃은 2종 중에서 고름 |
| 차량 신호 수신 | 기어, UX 제약, 주행거리, 와이퍼, 헤드램프, 창문, 도어, 조향, 브레이크, 앰비언트, 속도 |
| 신호 → 그림 | 헤드램프·해 진 시간 → 밤 톤, 창문 → 그림 속 차 창문, 정차 → 흐름 멈춤 |
| 오늘의 색 | 달·비·밤·곧은 길로 색을 계산해 P 체결 때 앰비언트 라이트에 1회 적용하고 하늘을 물들임. 주행 중 집계는 메모리에서 하고 P 체결 때 한 번 저장. 마지막 색을 저장해 앱을 다시 켜도 하늘 물들임이 이어짐(실내 조명에는 다시 쓰지 않음) |
| 숲 성장 | **앱을 켠 주행만** P 체결 때 구간 거리(누적 주행거리 차분)로 성장량을 더해 저장. 누적으로 숲 7단계(나무 수), 이번 달 누적으로 들판 밀도, 주행 신호로 개울·웅덩이·새·홀씨·반딧불·달. 줄어드는 경로 없음. 앱을 다시 켜도 그대로. 주행 중에는 바뀌지 않음 |
| 도착 성장 연출 | P 체결 약 4초 뒤부터 이번 주행으로 새로 보이게 된 요소만 하나씩 0.8초에 걸쳐 밑단에서 자라남(0.15초 간격). 반짝임·축하 문구·숫자 없음. 그 뒤 버튼. D로 바꾸면 남은 연출 없이 다 자란 모습 |
| P 지점 좌표 | FusedLocation 1회 조회 → 반경 200 m 안이면 같은 장소로 보고 방문 횟수만 올림. 경로는 저장하지 않음 |
| 첫 실행 권한 안내 | 기어 P에서 풍경 위 카드. 용도, 시스템 창에 보일 문구, 거부했을 때 달라지는 점을 먼저 알리고, 거부하면 결과를 한 번 알림. 카드 뒤 풍경은 흐리게 |
| 주차 화면 | P 체결 때 도착 인사 한 줄 + 음성(오늘 달린 길과 날씨, 운전 평가 없음), 그 뒤 [음성 기록]·[설정]. **기어가 P가 아니거나 플랫폼이 DO를 요구하면 즉시 숨김** |
| 음성 기록 | 주행 중 오른쪽 아래 버튼 한 번 → 받아쓴 **글만** 그 주행에 저장(오디오·녹음 위치는 저장 안 함) → 도착지에 묶임. 주차 중에 시간순 목록, 확인·수정·삭제 |
| 설정 | 실내 조명 연동 켜고 끄기, 주차한 곳 남기기 켜고 끄기, 권한 다시 묻기, 기록 모두 지우기 |
| 기록 저장 | 앱 전용 저장소의 파일 하나(주행·P 지점·음성 기록 글). 백업에서 제외해 앱을 지우면 함께 사라짐 |
| 주행 중 표시 | `distractionOptimized` 선언으로 D에서 앱이 가려지지 않음 |
| 주차 화면 움직임 | 버튼을 누르는 동안 살짝 작아짐(0.1초), 판이 열리고 닫힐 때 0.16~0.24초 옅게 미끄러짐, 목록·카드가 위에서부터 차례로 나타남, 권한 카드 등장·닫힘. 튕김·반복 없음. **기어가 P에서 벗어나면 움직임을 기다리지 않고 즉시 숨김.** 표시 수준 Lv3와 시스템 '애니메이션 삭제'(animator 배율 0)에서는 움직이지 않음. 주행 중 음성 버튼은 움직이지 않고 상태만 바뀜(누르면 바탕이 조금 짙어짐, 듣는 동안 테두리) |
| 주행 제한 강화 → 최소 화면 | 플랫폼 UX 제한(`activeRestrictions`)에 평소 주행(`NO_VIDEO`·`NO_SETUP`) 밖의 비트가 켜지면 즉시 세로 그라데이션 한 장(Lv3)으로 바꾸고, 평소로 돌아오면 원래 화면으로 돌아옵니다. 전환 연출은 없습니다 |

### 1차 이후로 미룸 (이 APK에 없음)

| 항목 | 현재 상태 |
|---|---|
| **전국 지도** | 지도 화면, 장소 목록, 장소 이름 붙이기, 장소 하나 지우기는 없습니다. 장소는 저장되지만 화면에는 "도착한 곳: 방문 n회"로만 보입니다 |
| **주차 중 음성 기록 추가** | 음성 기록은 주행 중에만 새로 남깁니다 |
| **표시 수준 Lv2** | 사용자가 고르는 정적 화면(Lv2)은 없습니다. 제한 강화 때의 Lv3 전환만 있습니다 |
| **차종 선택** | 기본 아반떼 고정입니다. 그랜저·투싼 도형은 있고 debug 조작으로만 바꿉니다 |
| **일부 에셋** | 가는 나무·개울은 자리표시, 여름·겨울 들판은 봄·가을 형태를 빌려 씁니다 |

### 확인하지 못한 것

- **실제 제한 강화로 Lv3 전환을 확인하지 못했습니다.** 에뮬레이터 설정에서 평소보다 강한 제한(`0x1ff`)은 주행 상태를 알 수 없을 때만 걸리고, 그 상태는 Virtual Console로 만들 수 없습니다. 같은 값을 debug 빌드에 주입해(`--ei uxActive 511`, 해제 `-1`) 전환을 확인했고, 판정 규칙은 단위 테스트로 확인했습니다
- 실차 동작과 실차 성능. 위 수치와 동작은 모두 에뮬레이터 결과입니다
- **실제 주행으로 늘어나는 주행거리.** 에뮬레이터는 거리를 적분하지 않아 숲 성장은 Console로 넣은 누적 주행거리로만 확인했습니다. 값을 받는 SDK 경로는 실차와 같지만, 실차가 얼마나 자주 값을 보내는지는 모릅니다
- 도착 성장 연출 중의 프레임 수치는 따로 재지 않았습니다
- 주차 화면 움직임은 에뮬레이터 화면 녹화로만 확인했습니다. 실차 화면에서의 체감 속도는 모릅니다
- 실제 말에 대한 음성 인식 품질. 에뮬레이터의 인식은 고정 문장을 돌려줍니다
- 설정의 [시스템 설정] 버튼(권한 창이 다시 뜨지 않을 때 앱 정보 화면 열기)
- 실차에서 꺼진 실내 조명에 색을 썼을 때의 동작
- 등록 카테고리(Lifestyle)에서 주행 중 표시가 App Market 심사를 통과하는지

## 개인정보와 네트워크

이 프로토타입은 위치·음성을 차 밖으로 보내지 않습니다. 앱 코드에 네트워크 호출이 없습니다. 차 안에 저장하는 것은 주차한 곳의 좌표 한 점과 방문 횟수, 음성 기록의 받아쓴 글, 풍경 상태(누적 거리·성장량·요소 종류와 개수·마지막 오늘의 색)뿐입니다. 이동 경로, 녹음 위치, 오디오, 속도는 저장하지 않습니다. 기록은 앱 전용 저장소에 있고 백업에서 제외했으므로 앱을 지우면 함께 사라집니다. 앱 안 설정에서 음성 기록을 하나씩, 또는 모든 기록을 지울 수 있습니다. 모두 지워도 풍경은 남기고, 요소가 어느 주행에서 언제 생겼는지만 지웁니다. APK의 `INTERNET` 권한은 SDK 라이브러리 매니페스트가 합쳐 넣은 것입니다. 앰비언트 라이트 제어(`CONTROL_CAR_LIGHTS`)는 개발 단계에서는 승인 없이 쓸 수 있고, 실제 배포 때는 App Market 심사 승인이 필요합니다.

## 프로젝트 구조

| 경로 | 내용 |
